Source

Fournir un paquet ZIP contenant exactement un fichier JSON de configuration de publication (publication_config.json) et les fichiers d'entrée (XML dramatiques, notices DOCX ou XML, préfaces, assets). Les chemins du JSON doivent être relatifs à la racine du ZIP.

Structure du paquet source de publication

Un paquet de publication est un fichier ZIP contenant un unique fichier publication_config.json et tous les fichiers source référencés par ce JSON. Le fichier JSON fait foi : il indique où se trouvent les textes dramatiques, notices, préfaces, dramatis personae et éventuels fichiers graphiques.

La structure de référence est celle produite par le Constructeur de site : le fichier publication_config.json est placé à la racine du ZIP, et les fichiers d’entrée sont regroupés dans un dossier sources/.

Exemple avec deux pièces :

publication_source.zip
├── publication_config.json
└── sources/
    ├── britannicus.xml
    ├── britannicus_notice.docx
    ├── britannicus_preface.docx
    ├── britannicus_dramatis.xml
    ├── phedre.xml
    ├── phedre_notice.docx
    ├── phedre_preface.docx
    ├── phedre_dramatis.xml
    ├── accueil.docx
    ├── introduction.docx
    └── logo.png

Dans cet exemple :

  • sources/britannicus.xml et sources/phedre.xml sont les XML-TEI des textes dramatiques ;
  • sources/britannicus_notice.docx et sources/phedre_notice.docx sont les notices, en DOCX stylé léger ou en XML-TEI ;
  • sources/britannicus_preface.docx et sources/phedre_preface.docx sont les préfaces, facultatives ;
  • sources/britannicus_dramatis.xml et sources/phedre_dramatis.xml sont les dramatis personae, en XML-TEI ;
  • sources/accueil.docx et sources/introduction.docx peuvent contenir la page d’accueil et l’introduction générale ;
  • sources/logo.png contient un logo ou un élément graphique commun au site.

Le fichier publication_config.json décrit ensuite l’ordre des pièces et l’association entre les fichiers. Tous les chemins y sont relatifs à la racine du ZIP. 

{
  "schema": "ets.site_publication_dialog_config",
  "version": 3,
  "metadata": {
    "author_name": "Jean Racine",
    "corpus_title": "Théâtre complet",
    "scientific_editor": ""
  },
  "xml_sources": {
    "home_page_tei_path": "sources/accueil.docx",
    "general_intro_tei_path": "sources/introduction.docx"
  },
  "plays": [
    {
      "play_slug": "britannicus",
      "dramatic_xml_path": "sources/britannicus.xml",
      "notice_xml_path": "sources/britannicus_notice.docx",
      "preface_xml_path": "sources/britannicus_preface.docx",
      "dramatis_xml_path": "sources/britannicus_dramatis.xml"
    },
    {
      "play_slug": "phedre",
      "dramatic_xml_path": "sources/phedre.xml",
      "notice_xml_path": "sources/phedre_notice.docx",
      "preface_xml_path": "sources/phedre_preface.docx",
      "dramatis_xml_path": "sources/phedre_dramatis.xml"
    }
  ],
  "play_order": [
    "britannicus",
    "phedre"
  ],
  "output": {
    "output_dir": null
  },
  "assets": {
    "logo_paths": [
      "sources/logo.png"
    ],
    "asset_directories": []
  },
  "options": {
    "show_xml_download": true,
    "build_latex_pdf": false,
    "hide_minor_variants_in_pdf": false,
    "publish_notices": true,
    "publish_prefaces": true,
    "include_metadata": true,
    "resolve_notice_xincludes": true
  }
}

Les chemins indiqués dans le JSON doivent toujours être relatifs à la racine du ZIP. Il ne faut donc pas utiliser de chemins absolus comme C:\... ou /home/..., ni de chemins contenant ../.

D’autres organisations internes peuvent être compatibles si le JSON pointe correctement vers les fichiers, mais, pour éviter les erreurs, il est recommandé d’utiliser la structure publication_config.json + sources/, qui est celle exportée par le Constructeur de site.
